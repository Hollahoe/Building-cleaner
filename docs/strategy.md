# 전략: 직접 → 반자동 → 플랫폼

## 한 문장

**지금은 플랫폼을 만들지 않고 직접 뜁니다.** 직접 뛰면서 반복이 확인된 업무만 나중에 도구로 만듭니다.

## 왜 직접 뛰는 게 먼저인가

| | 플랫폼부터 | 직접 뛰기부터 |
|---|---|---|
| 초기 비용 | 앱 개발, 건물주 모집, 업체 모집을 한꺼번에 해야 함 | 카톡·엑셀·노션만 있으면 됨 |
| 닭과 달걀 문제 | 건물주가 없으면 업체가 안 오고, 업체가 없으면 건물주가 안 옴 | 건물주 3명과 업체 몇 곳만 있으면 시작 가능 |
| 배우는 속도 | 출시 전까지 건물주가 실제로 뭘 아파하는지 모름 | 1–2주 인터뷰로 고통 순위가 나옴 |
| 돈 들어오는지 확인 | 수개월 뒤 | 첫 번째 절감 계약이 성사되는 시점 |
| 단점 | 확장성은 좋지만 텅 빈 플랫폼이 될 위험 | 운영자의 시간이 많이 듦 |

조언의 핵심은 "앱을 버려라"가 아니라 **앱과 관리 서비스를 함께 가져가되, 순서를 바꾸라**는 것입니다.
진단 도구(청진기)는 한 번 쓰고 떠나는 도구이고, 건물관리는 매달 반복되는 서비스입니다.

## 3단계

### 1단계: 직접 뛰기 (지금 ~ 3개월), 콘시어지형 건물관리

- 운영자가 건물주의 총무가 됩니다. 업체 견적, 점검 일정, 민원 응대, 서류 정리를 대신 합니다.
- 도구: 카톡(소통), 엑셀([`tools/savings-calculator.xlsx`](../tools/savings-calculator.xlsx)), 노션(이 레포를 가져온 것).
- 목표: 파일럿 건물 3개, 절감 사례 1건 이상, 케이스 스터디 1개.

### 2단계: 반자동화 (3 ~ 9개월), 공동구매 묶기

- 1단계 [이슈 로그](../ops/issue-log.csv)에서 **반복 횟수가 많고 처리 시간이 긴 업무**부터 자동화합니다.
- 청진기는 이 단계에서 **건물주를 모으는 무료 진단 도구**로 연결합니다. 연결 방식은 [README의 분리 원칙](../README.md#청진기와의-분리-원칙)을 따릅니다.
- 업체 계약을 묶어서 단가를 협상합니다(건물 5–10채 단위).

### 3단계: 플랫폼화 (9개월 ~), 마켓플레이스

- 업체 입찰, 공동구매 자동 견적, 관리비 대시보드.
- 이 시점에는 투자 유치도 선택지가 됩니다.

## 단계 전환 기준

느낌으로 넘어가지 말고, 아래 숫자로 판단합니다. 숫자는 [건물 대장](../ops/buildings.csv)과 [이슈 로그](../ops/issue-log.csv)에서 셉니다.

**1단계 → 2단계** (모두 충족)
- [ ] 돈을 내는 건물이 3개 이상
- [ ] 실제 고지서로 증명할 수 있는 절감 사례가 1건 이상
- [ ] 같은 유형의 업무가 한 달에 10회 이상 반복됨(이슈 로그의 `반복여부` 기준)

**2단계 → 3단계** (조언에서 제시한 기준)
- [ ] 관리하는 건물이 30개 이상
- [ ] 같은 견적 요청이 10번 이상 반복됨
- [ ] 업체 쪽에서 먼저 "우리도 넣어달라"고 연락이 옴

## 이 기준으로 헷갈릴 때 판단하기

- **직접 뛰는 게 맞는 경우**: 건물주가 "믿고 맡길 사람 없나" 하고 찾는 경우. 관리비 절감, 민원 해결처럼 사람이 직접 해야 하는 일인 경우. **지금이 여기에 해당합니다.**
- **플랫폼이 맞는 경우**: 위의 2단계 → 3단계 기준을 충족한 경우.

## 지금 하지 않을 것

- 앱, 웹사이트, 회원가입, 결제 시스템 개발
- 건물 10개 이상을 한 번에 받기(파일럿은 3개까지)
- 연면적이 큰 건물(파일럿은 30–100평 규모의 꼬마빌딩, 상가주택, 원룸 건물)
- **임대차 중개, 보험 모집, 세무·법률 알선을 하고 수수료 받기**: [법률 체크리스트](legal-checklist.md)를 먼저 확인
- 운영자가 직접 청소·시공하기: 업체를 관리하는 역할에 집중([서비스 범위](../service/scope.md) 참고)

## 예상되는 문제와 대응

건물관리를 하다 보면 누수, 세입자 민원, 공사 하자, 계약 분쟁이 생깁니다. 이 경험은 나중에 직접 건물을 살 때 그대로 공부가 됩니다.
대신 아래 장치를 처음부터 갖춥니다.

| 위험 | 대응 |
|---|---|
| 업체 하자 때문에 책임 공방이 생김 | 업체 계약은 **건물주 명의로 직접** 맺고, 운영자는 선정과 관리만 맡음([계약서 초안](../service/contract-draft.md)) |
| "절감 못 했는데 수수료 받았다"는 분쟁 | 절감액 산정 기준을 계약서에 숫자로 적음([가격 모델](../service/pricing.md)) |
| 민원이 쌓이는데 기록이 없음 | 모든 접수 건을 [이슈 로그](../ops/issue-log.csv)에 기록 |
| 법정 점검을 놓쳐 과태료가 나옴 | [법정 점검 캘린더](../ops/compliance-calendar.md)를 매달 확인 |

## 장기 목표와 연결

관리하는 건물이 3개, 10개, 30개로 늘면 운영자는 그 동네 건물 사정을 가장 잘 아는 사람이 됩니다.
어느 건물에 공실이 많은지, 어느 건물 관리비가 새는지, 어느 건물주가 매각을 고민하는지 알게 됩니다.

**관리 → 분석 → 매입.** 관리하면서 하자와 세입자 구성을 이미 아는 건물 중에서 가장 좋은 건물을 골라 직접 매입하는 것이 장기 경로입니다.
단, 관리 고객의 매각 정보를 본인 매입에 활용하는 것은 이해충돌 문제가 생길 수 있습니다.
그 시점이 오면 건물주에게 이해관계를 공개하고 독립적인 가격 평가를 받으세요.
