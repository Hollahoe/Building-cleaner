# 플랫폼 전략: 창구와 공동구매 모집판

## 결정

**지금 웹 창구를 엽니다.** 건물주가 찾아오고, 신청을 남기고, 공동구매가 모이는 걸 눈으로 볼 수 있는 곳이 있어야 영업도 신뢰도 생기기 때문입니다.

다만 만드는 범위는 **사람이 직접 뛰는 운영을 돕는 데까지**입니다. 업체 입찰, 자동 견적, 결제 같은 마켓플레이스 기능은 건물이 쌓인 뒤 만듭니다([전략 6번](strategy.md#6-3단계-로드맵과-전환-기준)).

| | 지금 만든 것 (v0) | 나중에 (v1, v2) |
|---|---|---|
| 건물주 | 첫 화면, 무료 진단 신청, 공동구매 목록·상세·참여 신청 | 내 건물 진행 현황, 카톡 알림 |
| 공동구매 | 운영자가 업체 견적을 먼저 받아 라운드를 열고, 모인 건물 수에 따라 단가 구간이 내려가는 걸 보여 줌 | 업체가 직접 입찰, 자동 견적 |
| 운영자 | 신청자 관리, 라운드 생성·수정, 참여자 상태 관리, 엑셀(CSV) 내보내기 | 관리비 대시보드, 월간 보고 자동 생성 |
| 돈 | 사이트에서 결제하지 않음 | (필요할 때 검토) |

## 왜 이 범위인가

1. **닭과 달걀 문제를 운영자가 끊습니다.** 업체를 플랫폼에 입점시키지 않고, 운영자가 견적(1채 / 3채 / 5채 / 10채 단가)을 먼저 받아 라운드를 엽니다. 건물주는 첫날부터 실제 숫자를 봅니다.
2. **모이는 게 보여야 모입니다.** "3채 더 모이면 1채당 월 ○원"이라는 진행 막대가 이웃 건물주에게 보낼 가장 강한 카톡 메시지입니다.
3. **법적으로 막힌 곳에 들어가지 않습니다.** 라운드 항목은 시설 용역(청소, 승강기, 소방, CCTV·보안, 방역, 저수조·정화조, 기타 시설 용역)만 고를 수 있게 코드에서 막아 뒀습니다. 보험·세무·법률·임대 중개는 넣을 수 없습니다([법률 체크리스트](legal-checklist.md)).
4. **결제가 없으니 위험이 작습니다.** 계약과 대금은 건물주와 업체가 직접 주고받습니다. 사이트는 신청과 연락처만 다룹니다.

## 사이트에서 일어나는 일

```
카톡·카페·전단 ──▶ 첫 화면 ──┬──▶ 무료 진단 신청 ──▶ 운영자 연락 ──▶ 진단 리포트 1장
                             │                                         │
                             └──▶ 공동구매 상세 ──▶ 참여 신청 ◀────────┘
                                                      │
                                                      ▼
                                 운영자 확인 ──▶ 건물주-업체 직접 계약 ──▶ 월간 보고
```

## 라운드 운영 규칙

- **한 라운드 = 한 동네 + 한 항목.** 예: "망원동 계단·복도 청소 1차". 업체 동선이 짧아야 단가가 내려갑니다.
- **단가 구간은 실제 견적서 숫자만.** 관리자 화면의 단가 칸에 추정치를 넣지 마세요. 견적서는 [`sourcing/vendors.csv`](../sourcing/vendors.csv)에 함께 기록합니다.
- **마감일과 목표 건물 수를 정합니다.** 마감일이 지나면 참여 버튼이 자동으로 사라집니다.
- **목표를 못 채워도** 모인 수에 맞는 구간 단가가 적용됩니다. 그 단가가 지금보다 비싸면 건물주는 계약하지 않아도 됩니다.
- **업체 대가 공개.** 라운드마다 "운영자 보수·업체 대가 공개" 칸이 필수입니다. 받는 게 없으면 "없음"이라고 적습니다.
- **상태:** 준비 중(비공개) → 모집 중 → 모집 마감 → 성사, 또는 취소(비공개).

## 개인정보

검색으로 확인한 기준(개인정보 보호법 제17조·제22조를 해설한 2차 자료)에 맞춰 동의를 나눴습니다. 법령 원문은 확인하지 못했으니 출시 전에 전문가 검토를 받으세요.

| 동의 | 필수/선택 | 안 하면 |
|---|---|---|
| 개인정보 수집·이용 | 필수 | 연락할 수 없어서 신청이 접수되지 않음 |
| 업체 견적용 건물 정보 제공(공동구매만) | 선택 | 그래도 참여 가능. 업체에 건물 정보를 넘기지 않고 현장 확인 일정을 따로 잡음 |
| 새 공동구매 소식 받기 | 선택 | 그래도 신청 가능 |

- 업체에는 **건물 위치(구·동), 유형, 연면적, 층수만** 넘깁니다. 이름·전화번호는 넘기지 않습니다.
- 관리자 화면에 "업체 정보 제공: 미동의 (업체에 건물 정보 전달 금지)"가 표시됩니다.
- 개인정보처리방침(`/privacy`)의 보유 기간(1년), 책임자, 연락처는 출시 전에 실제 값으로 채우세요.

## 출시 체크리스트

- [ ] **브랜드 이름 정하기.** 지금은 "모아관리(가칭)"입니다. 특허정보검색(KIPRIS)에서 상표를 확인하고 `BRAND_NAME`에 넣기
- [ ] **도메인 사기** (예: 브랜드 이름 .kr / .com)
- [ ] **호스팅 정하기.** Docker를 돌릴 수 있고 **재시작해도 지워지지 않는 디스크**를 붙일 수 있는 곳(예: Render, Fly.io, Railway, 일반 VPS). 요금은 각 서비스에서 확인하세요. 디스크를 안 붙이면 신청 기록이 사라집니다
- [ ] 환경 변수 설정: `ADMIN_PASSWORD`(길고 무작위로), `COOKIE_SECURE=true`, `DATABASE_PATH=/data/app.db`, 연락처, 카톡 채널 링크([`.env.example`](../.env.example))
- [ ] 사업자등록 후 꼬리말 사업자 정보(`BUSINESS_INFO`)와 개인정보 보호 책임자(`PRIVACY_OFFICER`) 채우기
- [ ] 개인정보처리방침·이용 안내 문구를 변호사나 개인정보 전문가에게 1회 검토
- [ ] 첫 화면 '비용' 문구(`FEE_TEXT`)를 확정된 보수 조건으로 바꾸기
- [ ] 첫 라운드: 정한 구에서 청소 견적 2곳 이상 받은 뒤 개설
- [ ] DB 백업: 주 1회 `app.db` 파일을 내려받아 보관(관리자 화면의 CSV 내보내기도 함께)

## 지표 (관리자 화면과 CSV로 셉니다)

| 지표 | 보는 곳 | 의미 |
|---|---|---|
| 주간 진단 신청 수 | 관리자 요약 | 창구에 사람이 오는가 |
| 신청 → 연락함 → 진단 완료 → 계약 전환 | 진단 신청 상태 | 어디서 빠지는가 |
| 라운드 충족률 (모인 수 / 목표) | 관리자 요약 | 공동구매가 실제로 모이는가 |
| 참여 → 확정 전환 | 참여자 상태 | 신청이 계약으로 이어지는가 |
| 업체 정보 제공 동의율 | 참여자 CSV | 견적 속도에 영향 |

## 청진기와의 분리

- 이 사이트는 새로 작성한 코드입니다(`app/`). 청진기 코드를 복사하거나 참조하지 않았습니다.
- DB, 도메인, 비밀번호, 배포 환경을 따로 씁니다.
- 나중에 청진기를 무료 진단 도구로 연결하더라도, 링크나 결과값 전달처럼 **데이터만 주고받는** 방식으로 연결합니다.
